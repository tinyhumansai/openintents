# SDKs

| Path | Package | Registry |
| --- | --- | --- |
| [`typescript/`](typescript) | `@tinyhumansai/openintents` (SDK + `openintents` CLI) | npm |
| [`python/`](python) | `openintents` (sync + async) | PyPI |
| [`rust/`](rust) | `openintents` (async; CLI behind `--features cli`) | crates.io |
| [`skill/openintents/`](skill/openintents) | Agent skill (`SKILL.md`) | |
| [`plugin-claude/`](plugin-claude) | Claude Code plugin (MCP server + skill) | this repo's marketplace |
| [`examples/`](examples) | One runnable example per language | |

All three SDKs implement the same surface, generated by hand from
[`../spec/openapi.yaml`](../spec/openapi.yaml). Every create (intents,
customers, top-ups, sessions), `cancel`, an answer to an input request,
session `release` and session command sends an `Idempotency-Key`, so a
retry never runs anything twice;
making a profile is idempotent by itself. Intents can be bought for, and
listed by, a `customer`. Event streams follow a timeline over Server-Sent
Events: they resume after a dropped connection with `Last-Event-ID`, and end
when the API answers `204` (the timeline is over).

Errors carry the API's `status`, `type` (`kind` in Rust), `code`, `param` and,
with `profile_busy`, the `lease` that says what holds the profile.

`wait` returns when the intent is final, or waits on a person: a step in
the payer's wallet (`requires_payment`, `returnOnPayment` /
`return_on_payment`), an answer from the payer while the agent signs them in
to the shop or for a `detail` the purchase needs (`requires_input`,
`returnOnInput` / `return_on_input`;
a detail's choices are in `input_request.options`), or the payer's sign-in
to the shop (`requires_login`, `returnOnSignIn` / `return_on_sign_in`). All
three are on by default.

The `openintents` command exists twice, with the same commands and flags: the
npm package, and the Rust crate behind `--features cli` (which lacks only
`mcp`). Commands: `run`, `status`, `list`, `cancel`, `input`, `pay`, `balance`,
`customers`, `sessions`, `profiles`, `topups`, `sign-ins`, `secrets` and
`login`. A change to one CLI is a change to the other.

Versions move together: the three packages, the skill and the plugin always
carry one version, and npm, PyPI and crates.io publish it together.
`node sdk/bump-versions.mjs <patch|minor|major|current|x.y.z>` bumps all of
them, and `node sdk/bump-versions.mjs --check` fails when any file disagrees
(CI runs it). The release workflow refuses a version a selected registry
already has and, with all three selected, checks afterwards that `npm view`,
`pip index versions` and `cargo search` show it.
